# 数据目录与升级

这篇文档讲清楚数据放在哪、升级时会发生什么、需要备份或清理时怎么做。

## 数据目录

所有运行时数据都在用户主目录下的 `~/.cannbot-tui/`（Windows 为 `C:\Users\<用户名>\.cannbot-tui\`），主要包括：

- 配置与登录信息；
- 会话历史与分组记录；
- 运行日志。

多开实例时，各实例的数据互不干扰。

## 登录数据与安全边界

- 访问令牌只在程序运行期间使用，不会写入本地文件。
- 登录凭据在本机加密保存，并与当前设备绑定；换机器、重装系统或更换系统用户后需要重新登录。
- 本地不会保存明文访问令牌，各智能体也不会拿到真实访问令牌。
- 分享日志或截图前请先检查内容，避免带出本机路径、用户名等信息。

## 日志

- 默认记录常规运行信息；设置环境变量 `CANNBOT_DEBUG=1` 可额外记录调试日志：

```bash
CANNBOT_DEBUG=1 cannbot
```

- 日志会自动轮转并清理较早内容，无需手工维护。
- 排障时把日志目录里最新的日志文件提供给维护者即可，不需要提供其它数据。

## 升级

### 自动更新提示

在交互式终端启动时，程序会检查 npm 上是否有新版本，有更新时给出三个选项：

| 选项 | 作用 |
| --- | --- |
| `1` 更新 | 就地执行全局安装，完成后重新执行 `cannbot` |
| `2` 跳过 | 本次不更新，下次启动再提示 |
| `3` 跳过此版本 | 记住该版本，不再为它提示（更高版本仍会提示） |

以下情况不会触发检查：

- `cannbot -h`、`cannbot --help`、`cannbot -v`、`cannbot --version`；
- `cannbot acp`；
- 标准输入或输出不是交互终端（例如被脚本调用）；
- 设置了 `CANNBOT_NO_UPDATE_CHECK=1`。

检查网络异常不会阻塞启动，程序会直接用当前版本继续。

### 手动升级

手动安装最新版本：

```bash
npm install -g cannbot
```

升级后界面与内置智能体 `cannbot-cli` 会一起更新，无需单独升级智能体。配置与历史都保留在 `~/.cannbot-tui/`，但涉及登录凭据格式变化时需要重新登录。

## 备份与清理

- 备份：关闭所有 CANNBot 实例后，复制整个 `~/.cannbot-tui/` 目录即可（含历史、分组与配置）。
- 重置：关闭程序后删除或重命名 `~/.cannbot-tui/`，下次启动会重新创建。这会丢失历史、分组与登录态，请先备份。
- 只想清空登录态：用 `/logout`，不要删目录。
- 只想清空历史：在界面里逐个删除会话或分组，比直接改数据文件安全。

## 命令行标志

| 命令 | 作用 |
| --- | --- |
| `cannbot` | 启动交互界面 |
| `cannbot -h` / `--help` | 显示帮助并退出（优先于版本输出） |
| `cannbot -v` / `--version` | 显示当前版本并退出 |
| `cannbot acp [参数...]` | 不启动界面，把参数透传给内置智能体的 ACP 服务 |

帮助与版本由启动器本地回答，不依赖平台二进制定位；`acp` 需要内置智能体可用，否则会直接报错退出。

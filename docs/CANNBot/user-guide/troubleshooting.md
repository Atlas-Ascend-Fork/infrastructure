# 常见问题与排障

这篇文档按症状列出最常见的几类问题与处理方式。

## 启动失败

提示缺少当前平台的运行文件，或提示内置 `cannbot-cli` 不可用时，通常是安装不完整：

```bash
npm install -g cannbot
```

重新完整安装后再执行 `cannbot`。安装时不要使用 `--omit=optional`。

## macOS 上提示无法打开或“已损坏”

macOS 上的两个可执行文件（界面与内置智能体）未做代码签名与公证，会被 Gatekeeper 拦住。下面的命令会关闭 macOS 对这两个文件的完整性与来源校验，**只应在确认包来源可信后执行**；操作后本机对该二进制的防护会永久降低，被篡改时系统不会再通过签名校验发现。

执行前请先确认：

1. 包来自可信的 registry（不是被替换的私有镜像或劫持的镜像），并已从官方渠道核对完整性信息（如 checksum）；
2. `npm root -g` 指向你预期的全局安装目录，输出的路径下确实是本次安装的 `@cannbot-release/...` 子包，而非其它位置。

确认无误后清除隔离标记：

```bash
for bin in cannbot cannbot-cli; do
  xattr -d com.apple.quarantine "$(npm root -g)/@cannbot-release/darwin-arm64/bin/$bin" 2>/dev/null || true
done
```

`xattr -d com.apple.quarantine` 只是移除该文件的“下载隔离”标记，让 Gatekeeper 不再拦截。

把路径中的 `@cannbot-release/darwin-arm64` 换成你实际安装的平台子包名。仍被拒绝时，可临时重新签名：

```bash
codesign --force --sign - "<可执行文件路径>"
```

`codesign --force --sign -` 会**覆盖可执行文件原有的签名信息**，替换为本地 ad-hoc 签名。此操作不可逆地丢弃原签名，之后该文件即使被篡改，也不会再被签名校验发现，请勿把它当作常规“修复”命令随手执行。

## 登录问题

登录失败或一直停在等待授权时：

1. 看浏览器是否已弹出；没有弹出就按 `Enter` 复制弹窗里的授权链接，手动在浏览器打开；
2. 完成授权后弹窗没有变化，可关闭弹窗后重新 `/login`；
3. 浏览器授权走不通时，改用 `/gitcode-token` 粘贴访问令牌。

之前能用、现在要求重新登录，通常是因为换机器、重装系统、更换系统用户，或执行过 `/logout`；重新登录即可。

## 会话与智能体

- **智能体带“（未安装）”**：系统里找不到对应命令。`cannbot` 是内置的，无需安装；其它智能体需要自行安装并能在终端直接运行（`opencode`、`codex`、`hermes`、`claude`）。
- **会话启动失败或立刻结束**：先确认所选智能体可用，可先用 `/harness` 切回 `cannbot` 验证登录与界面是否正常。
- **长时间停在“正在启动 …”**：首次启动会明显更慢，可先等待；期间可按 `Shift+←` 返回主页面，会话会在后台继续启动。长期无画面时查看日志。
- **会话中按键没反应**：除 `Shift+←`（返回主页面）与 `Ctrl+C`（退出程序）外，按键都由智能体处理。

## 升级与数据

- **自动更新失败**：手动执行 `npm install -g cannbot`。
- **想彻底重置或数据异常**：关闭所有实例并备份 `~/.cannbot-tui/` 后，删除或重命名该目录，下次启动会重新创建。不要手工编辑其中的数据文件。

## 上报问题时请附上

1. `cannbot -v` 的输出（版本号）；
2. 操作系统与终端类型；
3. 复现步骤与期望结果；
4. `~/.cannbot-tui/logs/` 下最新的日志文件（分享前检查是否含本机路径等敏感信息）。
